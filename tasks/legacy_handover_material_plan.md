# 전임자 인수인계 자료 구조화 계획

## 목적

`AIoT개발팀_오세영_인수인계자료`를 현재 Edge AIoT·EdgeX 운영 구조와 정부과제 증빙 기준에 맞게 재분류한다.
원본 자료는 삭제하거나 이동하지 않고 보존하며, 현재 운영 기준 문서와 과거 참고자료가 섞이지 않도록 문서 인덱스와 요구사항 추적표를 먼저 만든다.

## 분류 원칙

1. 원본은 삭제·덮어쓰기하지 않는다.
2. 구현 완료, 시뮬레이션 검증, 실제 장치 UAT 완료를 구분한다.
3. 현재 운영 경로는 `AI/센서 → MQTT → 규칙 → Action Layer → EdgeX → Device Service → 장치`를 기준으로 한다.
4. 제조사 프로토콜은 Device Service 내부 참고자료로 관리한다.
5. 정부과제 증빙자료에는 요구사항, 설계, 구현, 시험, 실증 결과의 연결 관계를 남긴다.
6. 비밀번호·토큰·개인정보는 문서 본문에 복사하지 않고 별도 보안 절차로 관리한다.

## 단계별 작업

### 1단계: 자료 분류와 목록화

- 루트 설계 문서, 디바이스 코드, Jetson 자료, 모델 산출물, 장비 증빙을 분류한다.
- `현재 기준`, `정부과제 증빙`, `기술 참고`, `레거시·보류` 상태를 부여한다.
- 이미지와 영상은 단순 파일 목록이 아니라 용도와 증빙 가능 여부를 기록한다.

### 2단계: 정부과제 요구사항 추적

- 과제 요구사항별 설계 문서, 구현 경로, 테스트, 실제 증빙을 연결한다.
- “구현 완료”와 “현장 실증 완료”를 별도 상태로 기록한다.
- 미검증 장치와 미확정 모델은 제한사항으로 명시한다.

### 3단계: 현재 기준 문서 재구성

- EdgeX 중심 아키텍처와 입력→출력 파이프라인을 기준 문서로 확정한다.
- 디바이스별 API/Device Service 문서를 분리한다.
- 모델별 데이터셋, 성능, Jetson 지연시간, 배포 여부를 정리한다.
- Docker, Jetson, MQTT, eKuiper, 장애 대응 런북을 연결한다.

### 4단계: 증빙 패키지 고정

- 시험 로그, 스크린샷, 영상, 모델 체크섬, 설정 버전을 릴리스 단위로 고정한다.
- 원본 파일의 출처와 작성·수정 시점을 기록한다.
- 외부 제출본과 내부 운영본을 분리한다.

## 완료 기준

- [ ] 전임자 자료의 논리적 분류가 완료됨
- [ ] 과제 요구사항 추적표에 구현·시험·실증 상태가 연결됨
- [ ] 현재 운영 문서와 레거시 자료가 분리됨
- [ ] 장치별 실제 연결 상태가 문서에 반영됨
- [ ] 모델 후보와 운영 모델이 구분됨
- [ ] 민감정보가 운영 문서에서 제거됨
- [ ] 모든 정부과제 증빙에 버전·출처·검증상태가 있음

## 주요 위험과 대응

| 위험 | 대응 |
|---|---|
| 과거 자료를 현재 완료 기능으로 오해 | 문서마다 기준일과 검증 상태 표시 |
| 실제 미연결 장치의 실증 오인 | `미연결`, `dry-run`, `실제 UAT`를 분리 |
| 모델 실험 지표의 과대 해석 | 데이터셋·분할·클래스·현장 성능을 함께 기록 |
| 원본 삭제로 과제 증빙 손실 | 원본 보존 후 인덱스만 추가 |
| 문서에 인증정보 노출 | 비밀값 마스킹 및 교체 절차 기록 |
