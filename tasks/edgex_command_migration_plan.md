# EdgeX 중심 장치 제어 전환 계획

## 목표

AI 탐지와 센서 이벤트를 EdgeX 기반 장치 제어 흐름으로 통합한다. 현장 제어의 실시간성을 유지하면서 기존 직접 호출 경로를 단계적으로 대체한다.

## 전환 원칙

- 기본값은 기존 직접 제어를 유지해 운영 중단을 방지한다.
- 먼저 Command 계약과 테스트를 고정한 뒤 발행기와 Device Service를 연결한다.
- 장치별 제어 결과는 요청·수락·완료·실패 상태로 추적한다.
- DB, 외부 API, 대시보드는 관찰·감사 경로로 두고 실시간 제어 경로와 분리한다.
- 각 단계는 독립적으로 되돌릴 수 있어야 한다.

## 단계

### 1단계: Command 계약 고정

- [ ] 장치 명령 요청 필드와 토픽 규칙 정의
- [ ] 요청 생성 함수 단위 테스트 작성
- [ ] 기존 직접 제어 동작에는 영향이 없는지 확인

### 2단계: EdgeX 명령 발행기 추가

- [ ] Action Layer에서 공통 발행기 인터페이스 사용
- [ ] `direct` 기본 모드와 `shadow` 비교 모드 제공
- [ ] 발행 실패·중복·상관관계 ID 기록

### 3단계: 장치별 EdgeX Device Service 연결

- [ ] 스피커 Device Service 추가
- [ ] 사이렌 Device Service 추가
- [ ] 전광판 Device Service를 기존 Dabit 서비스와 계약에 맞게 정리

### 4단계: 운영 전환

- [ ] 현장 테스트에서 direct/shadow 결과 비교
- [ ] 장치별 완료 응답과 타임아웃 확인
- [ ] 사이트 단위로 EdgeX 제어를 점진 활성화
- [ ] 롤백 절차 검증 후 기본 모드 변경

## 검증 기준

- 기존 자동·수동 승인 테스트가 모두 통과한다.
- 명령마다 동일한 `event_id`와 `request_id`를 추적할 수 있다.
- EdgeX 장애 시 기존 안전 정책과 재시도 정책이 동작한다.
- 장치 응답 지연과 현장 제어 지연을 별도로 측정한다.
