# 정부과제 증빙 등록 양식

## 사용 목적

요구사항 추적표의 각 항목을 실제 파일·로그·영상·시험 결과와 연결하기 위한 등록 양식이다. 원본은 별도 보존하고, 이 문서에는 경로와 식별정보만 기록한다.

## 증빙 항목

| 항목 | 기록 내용 |
|---|---|
| 증빙 ID | 예: `EV-SIGNBOARD-001` |
| 요구사항 ID | 추적표의 요구사항 식별자 |
| 증빙 유형 | 문서 / 코드 / 테스트 / 로그 / 스크린샷 / 영상 / 실제 장치 |
| 파일 경로 | 저장소 상대 경로 또는 보안 보관 위치 |
| 원본 출처 | 전임자 자료 / 현재 저장소 / 현장 수집 / 외부 업체 |
| 버전·체크섬 | 코드 커밋, 모델 버전, 파일 SHA-256 등 |
| 작성·시험 일시 | 표준 시간대 포함 |
| 시험 환경 | Jetson, Docker, 장치, 네트워크, 모델 설정 |
| 결과 | PASS / FAIL / 부분 성공 / 미검증 |
| 제한사항 | 실제 장치 여부, dry-run 여부, 재현 조건 |
| 담당자 | 확인 또는 후속 조치 담당자 |

## 등록 예시

| 증빙 ID | 요구사항 ID | 유형 | 근거 | 결과 | 제한사항 |
|---|---|---|---|---|---|
| EV-SIGNBOARD-001 | OUT-01 | 로그·테스트 | `tests/test_dabit_device_service.py` | PASS | 자동·계약 검증 |
| EV-SIGNBOARD-002 | OUT-01 | 실제 장치 | EdgeX Core Command 결과 로그 | 부분 성공 | 물리 화면 육안 확인 필요 |
| EV-SPEAKER-001 | OUT-02 | dry-run | Device Service 계약 점검 | PASS | 스피커 실제 연결 미완료 |
| EV-AI-FALL-001 | AI-01 | 모델 결과 | 고정 평가 리포트 | 부분 성공 | 현장 데이터 분할과 FPS 추가 필요 |

## 증빙 보존 규칙

- 원본 파일명과 수정일을 임의로 바꾸지 않는다.
- 제출본에는 계정·비밀번호·토큰·개인 연락처를 포함하지 않는다.
- 스크린샷은 화면만 보지 말고 실행 명령, 환경, 일시를 함께 기록한다.
- HTTP 200, MQTT 발행, 시뮬레이션 성공은 물리 장치 동작 성공과 분리한다.
- 모델 성능은 데이터셋 버전, 분할, 클래스, 임계값, 하드웨어를 함께 기록한다.
