# 장애 대응·에스컬레이션

## 장애 보고에 반드시 포함할 정보

발생 시각, 마지막 정상 시각, 서비스명, Jetson 장비명, camera_id/device_id, MQTT topic, event_id/command_id, 증상, 최근 변경, 관련 로그·스크린샷, 재현 여부를 함께 전달한다.

## 분류

| 분류 | 증상 | 1차 담당 | 다음 담당 |
|---|---|---|---|
| AI/모델 | bbox·pose·이벤트 누락, 오탐 증가 | AI 담당 | 데이터/모델 담당 |
| 영상/Jetson | RTSP 단절, GPU 오류, frame drop | 플랫폼 담당 | 장비 담당 |
| MQTT/EdgeX | 메시지·Reading·rule 누락 | 백엔드 담당 | EdgeX 담당 |
| 출력 장치 | 방송·표시·점등 실패 | 장치 담당 | 제조사/네트워크 |
| 보안 | 계정 노출·비인가 접근 | 보안 담당 | 관리자 |

## 기본 순서

1. 안전사고 가능성이 있으면 현장 담당자에게 먼저 알린다.
2. 장애 범위를 단일 카메라·장치인지 전체 시스템인지 구분한다.
3. health/readiness와 Docker 상태를 확인한다.
4. 원본 입력→정규화→규칙→Action→장치 순서로 끊긴 구간을 찾는다.
5. 최근 변경을 rollback할지 승인받는다.
6. 복구 후 같은 입력으로 재검증하고 장애 보고서를 닫는다.

## 운영 등급 예시

- P1: 실제 위험 이벤트가 장치에 전달되지 않거나 전체 현장 중단
- P2: 일부 카메라·장치 장애, 우회 운영 가능
- P3: 검색·대시보드·비긴급 속성 오류
- P4: 문서·개선 요청

운영 등급별 응답 시간과 연락처는 회사 SLA에 맞춰 `<현장 입력 필요>`로 채운다.
