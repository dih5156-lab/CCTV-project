# I31 — 추적 ID 저장·조회 보정

2026-09-28 · v0.47 · **FIXED_LOCAL / 운영 미반영** · [검증 근거](evidence/appearance_track_id_20260928.json)

10-12 후속 I63: 아래는 기존 DB 저장/조회 계약이다. 신규 AI 이벤트·관측·MQTT/EdgeX의 문자열 규격은 [공통 추적 ID 계약](../features/EVENT_SCHEMA_STANDARD.md#추적-id-계약--2026-10-12--i63)을 따른다. 과거 DB 행을 고치지 않으며 uint64 최댓값은 신규 추적 관측에서 미추적 값으로 구분한다.

DeepStream의 uint64 ID는 SQLite INTEGER의 signed int64 범위를 넘을 수 있다.
기존에는 `15509195771361624064` 같은 ID를 바인딩할 때 OverflowError가 발생해 의상 기록이 누락됐다.
또한 실패 전에 쿨다운을 갱신해 정상 재시도가 억제될 수 있었다.

## 변경 계약

- `appearance_log.track_id_text TEXT`를 추가해 정확한 10진 ID를 보존한다. 신규 저장은 문자열을 기준으로 한다.
- 기존 `track_id INTEGER`는 호환용으로 유지한다. signed int64 범위의 ID는 함께 저장하고 상위 uint64는 NULL로 둔다. 잘라내기·부동소수점 변환은 하지 않는다.
- 기존 행·인덱스를 재작성하지 않는다. 이전 행은 정수 열을 읽어 문자열 ID를 반환한다. 초기화 시 누락된 문자열 열만 추가하며 반복 초기화도 검증했다.
- Python 저장소 조회와 API의 기존 `track_id` 정수 응답은 유지한다. `/api/v1/search`에 `track_id_text`를 추가한다. 브라우저/외부 연동에서 정확한 비교·키 저장은 이 문자열 필드를 사용한다.
- 기존 음수 int64도 호환한다. bool·실수·문자열 입력 및 int64/uint64 범위 밖 정수는 저장하지 않는다. 알 수 없는 ID는 None으로 유지한다.
- 저장이 성공한 뒤에만 쿨다운을 갱신한다. 저장 실패는 rollback하고 정상 재시도를 허용한다.

영향 파일: `src/services/appearance_log.py`, `src/api/v1/search.py` 및 관련 테스트.
새 라이브러리는 없고 공통 이벤트/MQTT 계약·추적기·운영 설정은 변경하지 않았다.
직접 SQL로 읽는 연동은 `COALESCE(track_id_text, CAST(track_id AS TEXT))`를 사용해야 한다.
이전 앱으로 되돌리면 새 대형 ID 행의 정수 열은 NULL로 보인다. 운영 배포 시 DB 백업과
읽기 측 반영을 함께 준비해야 하며, 이번에는 운영 DB 마이그레이션을 수행하지 않았다.

## 검증

**67 PASS**, Ruff·변경 범위 diff 검사 PASS. 신규 회귀의 수정 전 결과는 13 FAIL / 2 PASS였다.
[JUnit](evidence/appearance_track_id_20260928.xml)에 큰 ID 경계·인접 ID 구분·카메라별 쿨다운,
DB 재개방·이전 스키마/행 보존·실제 FastAPI 응답·잘못된 입력 거부·저장 실패 후 재시도를 보존했다.

실제 격리 영상은 준비 후 35초 실행을 완료했고 의상 기록 **13건**이 원래 추적 ID와 정확히 일치했다.
이 실행에서 생성된 ID 2개는 signed int64 범위 안이었다. 따라서 범위 초과 해결 증거는 별도로 분리했다.
같은 임시 DB에 과거 실패 ID `15509195771361624064`, 인접 ID `15509195771361624065`,
uint64 최댓값 `18446744073709551615`를 저장하고, 재개방·API 직렬화까지 값의 동일성을 확인했다.
이는 저장 경계의 의도적 재현이며 실제 실행이 대형 ID를 생성했다고 주장하지 않는다.
