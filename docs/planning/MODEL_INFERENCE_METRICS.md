## 관측 의미

| 프레임 상태 | 관측 조건 | 의미의 한계 |
|---|---|---|
| `tensor_output` | 해당 GIE ID의 tensor 메타 존재 | 프레임당 1회. SGIE 객체 수는 별도 카운터. GPU 재실행/모델 판정 성공을 단정하지 않음 |
| `no_objects` | SGIE에서 읽은 객체 목록이 비어 있음 | 최종 메타 경계 기준. 각 모델의 클래스·크기 필터를 통과한 대상 ROI 수를 측정한 것은 아님 |
| `classifier_only` | tensor 없이 해당 GIE 분류 결과만 존재 | 캐시/비동기 여부 불명. 신규 tensor 출력으로 합산하지 않음 |
| `unobserved` | 관측 설정은 읽혔으나 해당 출력 메타 없음 | interval·ROI 필터·캐시 등 원인 미확정. 미추론 실패로 단정하지 않음 |
| `unknown` | 속성/메타 읽기 불가, tensor 비활성, GIE ID 충돌 | 미관측/정상 완료와 분리 |

활성 모델의 각 프레임은 위 5가지 중 하나이며 합은 `frames_seen`과 같다.
한 프레임에 tensor 객체와 분류만 있는 객체가 섞이면 프레임은 `tensor_output`,
객체 카운터 `objects_with_tensor`와 `objects_classifier_only`에는 각각 집계한다.
동일 객체의 중복 tensor 메타는 한 번만 센다. `object_id`로 캐시를 추측하지 않는다.
모델이 없으면 `enabled=false`이고 관측/경과 시간을 만들어내지 않는다.
enabled는 파이프라인 엘리먼트 존재 여부이며 카메라별 정책 활성이나 엔진 로드 성공과 다르다.

`last_frame_age_seconds`와 `last_tensor_age_seconds`는 monotonic 시계 기준이다.
분류 결과만 재등장해도 마지막 tensor 시각은 갱신되지 않는다. 첫 관측 전에는 null이며
Prometheus 경과 시간 표본도 없다. 촬영 시각·GPU 완료 시각·관제 ACK 시각과는 별개다.
등록되지 않은 source ID는 새 label을 만들지 않는다. 오류 프레임 다음 카메라는 계속 집계하고,
계측 예외가 이벤트 처리를 중단하지 않도록 한다.

파이프라인 재생성 시 카운터/경과 시간을 초기화하고 `pipeline_generation`을 올린다.
세대는 프로세스 내부 값이며 프로세스 재시작을 가로지르는 전역 ID가 아니다.
카운터 감소는 재생성/reset 가능성을 함께 확인해야 한다.

GObject의 `unique-id`, `process-mode`, `batch-size`, `interval`, `output-tensor-meta`는
설정 후 **pipeline_build 시점**에 캡처한다. 읽을 수 없는 속성은 null/지표 없음으로 남긴다.
이 값은 설정 파일 추정과 구분하지만 이후 동적 모델 갱신·엔진 해시·실제 GPU 로딩까지 보증하지 않는다.
09-22 실행 컨테이너에서 `gst-inspect-1.0 nvinfer` 읽기 전용 조회로 플러그인 7.1.0과
5개 속성 지원을 확인했다. 이는 실행 중인 파이프라인 인스턴스의 값 조회가 아니다.

NVIDIA 문서의 [Gst-nvinfer 메타 위치·캐시 동작](https://docs.nvidia.com/metropolis/deepstream/7.1/text/DS_plugin_gst-nvinfer.html)을 참고했다.
Primary는 frame user metadata, Secondary는 object user metadata를 읽는다.
분류 캐시가 있으므로 classifier 결과만으로 새 추론 완료를 판단하지 않는다.
