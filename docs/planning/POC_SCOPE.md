### 3.1 모듈별 실장비 적용 시점

**전체 개발 종료까지 실장비 시험을 미루지 않는다.** 모듈의 로컬 검증이 끝나면
필요한 선행 조건을 확인하고 아래 단계로 진행한다. P7의 현장팀 POC는 그 결과를
통합해 검증하는 별도 단계다. WBS 목표 주간은 해당 모듈의 통합 완료 목표이며,
읽기 전용 상태 확인이나 준비된 장치의 기초 점검을 그때까지 금지하는 날짜가 아니다.

| 순서 | 적용 범위 | 다음 단계로 넘어갈 근거 |
|---|---|---|
| 1. 로컬 모듈 검증 | 합성/저장 입력·임시 DB·모형 출력으로 계약과 오류/복구 확인 | 해당 변경의 테스트·미해결 이슈·영향 파일 기록 |
| 2. 실제 수신 읽기 확인 | 현재 CCTV/센서의 기존 로그·저장 기록·버전을 확인하고 원본과 공통 값 대조 | 실제 입력 시각·단위·ID·저장 흐름, 로컬 코드와 실행 코드 차이 |
| 3. 한 서비스 적용 | 적용 파일/이미지·이전 사본/백업·복구 명령·중단 범위를 준비하고 유지보수 범위 확인 | 실행 버전과 새 형식의 수신/저장 증거; 실패 시 복구 결과 |
| 4. 한 장치 시험 | 전광판부터 고정 이벤트 1건, 이후 스피커. 대상·중단 방법·현장 확인자 확정 | 명령/응답/DB ID와 실제 화면·음성 확인. ACK만으로 실물 합격 처리하지 않음 |
| 5. 모듈 연결·현장 POC | 영상/센서→저장→우선순위→각 장치/관제, 이후 동시 이벤트·부하 | 앞선 WBS 완료 조건 및 현장팀 POC 판정 |

09-18 현재 새 공통 관측·검증 코드는 **1단계의 로컬 검증 완료 범위**다. 이번 작업에서
서비스 재시작·출력 명령·GPU 시험을 실행하지 않았다. 기존 시스템의 과거 실장비
시험 성과와 새 코드의 적용 여부를 구분한다. 먼저 2단계로 실제 흐름을 대조하고,
운영 동작이 바뀌는 3/4단계는 구체적인 적용/복구 자료를 준비한 뒤 진행한다.

모든 로컬 변경을 한 번에 재시작해 반영하지 않는다. bind mount 소스와 이미지 소스의
반영 방법이 다르고 미커밋 변경이 많으므로 적용 대상만 따로 확인한다. 관제 선정
대기 중에는 내부 수신/저장을 검증하되 실제 관제 수신·표시 합격으로 보고하지 않는다.
