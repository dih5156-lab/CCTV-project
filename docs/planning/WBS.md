사용자 요청은 **12월 전 POC 진행 방법**이다. 기존 12월 POC/11-27 준비 기준선을 아래처럼 앞당기는 안을 제안한다. **11-20 내부 준비, 11-23~27 현장 시험, 11-30 재시험 여유**는 제안일이며 현장 예약 확정 기록이 아니다. 12-31 보완·인계 목표는 유지한다.

사용자가 **“11월에는 낙상·영상·센서/출력 중심의 1차 현장 POC, 전체 요구사항은 계속 완료”**를 선택했다. 1차는 기존 저장/관제 경로까지 연결해 확인한다. 시험 구성안은 실제 CCTV1대에서 시작해 가능하면2대, 온습도/기울기·전광판/스피커다. 정확한 대수·현장 시나리오/수치는 접근 조건과 함께 확정한다. 싸움·월담·실물4카메라·사이렌 등 전체 요구사항은 후속 완료 대상으로 유지한다. 제한된 현장 관찰은 P6.1~P6.4/P7.1의 전체 선행조건 완료나 최종 합격을 대신하지 않는다. 전체 범위를 11월에 모두 요구하면 P5.7/P5.8 및 확장 P5.6의 추가 공수·독립 평가 자료를 먼저 산정해야 하며 현재 일정 달성을 약속할 근거가 없다.

**시간 가정:** 10-19~11-20 평일25일×6시간=150시간, 결함·재시험 여유20%(30시간)를 제외한 작업 배정 상한은 약120시간이다. 11-23~27은 현장 시험/보완 30시간을 별도로 확보하는 안이다. 주5일·향후 가용시간은 미확정이고 오늘 기사용 시간·다른 업무·휴무를 차감해야 한다. 장기 무인 관측 시간과 실제 개발 투입 시간은 구분한다. 과거106~208시간은 추가 요구가 빠진 추정이므로 현재 전체 잔여 견적으로 재사용하지 않는다.

**NX 조건:** 현재 AGX로 공통 경로 검증을 계속하는 안을 우선한다. NX가 11월 POC 필수라면 **10-30까지 장비·JetPack/BSP·접속 조건 확보**를 제안하고 11-02~13에 보드별 엔진 생성·메모리/성능·복구 검증 시간을 재배정한다. 늦어지면 AGX로 대체 가능한지 사용자/현장팀이 결정하며 자동 대체하거나 NX 합격으로 표시하지 않는다. 추가 보드 검증은 무료 공수가 아니므로 다른 작업과 합쳐 재산정한다.

**진행/중단 판단:** 10-23 라이브 끊김 원인과 실측 결과, 10-30 단일 낙상·출력 경로, 11-06 장치 접근/연동, 11-13 다중·장애 시험을 점검한다. 각 시점 미달이면 남은 공수와 현장 범위를 즉시 재예측하며 기준을 낮춰 통과시키지 않는다. 11-20까지 핵심 경로가 미달이면 사용자/현장팀과 제한 관찰 또는 일정 변경을 결정한다.

**후속 전체 범위:** 싸움·월담·실물4대·사이렌·외부 관제 및 나머지 사양은 기존 WBS에 남긴다. 11-13에 데이터/장비 확보와 신규 모델 잔여 공수를 재산정해 12-31 목표 영향을 보고한다. 1차 범위 확정을 전체 요구의 12월 완료 보장으로 해석하지 않는다.

**기술 선택:** 기존 DeepStream·Python 제어/API 경로와 H264 최소 수정 후보를 재사용한다. C++ 전체 이식, 새 파이프라인 교체, 새 모델 동시 도입은 이번 준비안에 추가하지 않는다. 반복 실측으로 특정 Python callback 병목이 남을 때만 해당 함수/플러그인의 제한적 C++ 이식 공수를 따로 판단한다. 싸움 보류 상태를 이번 계획만으로 해제하지 않으며 전체 POC 선택 시 재개 순서·공수 재산정이 필요하다. KISA 시험/인증 일정도 별도 미확정으로 남긴다.

이번 변경은 **사용자가 확정한 1차 범위와 미확정 현장 일정 제안 기록**이다. 작업 상태 DONE9/37, P5.1/P5.2 IN_PROGRESS, P6.4 PLANNED, I54/I56/I07 OPEN을 유지하며 새 GPU 시험·서비스 전환·실물 출력은 수행하지 않았다.
