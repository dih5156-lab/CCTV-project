# P0.3 — 성능 위험과 다음 검증 경로

2026-09-18 · 기준 갱신2026-10-07 · P0.3 **DONE: 기존 자료 검토·검증 경로 결정** · R09 성능 합격은 미완료

## 판단

10-07 사용자 합의: 실물4카메라 목표를 유지하고 **AI 실제 추론은 우선 카메라별 약15FPS**를 시험한다. 입력/출력 영상 FPS와 AI 추론 FPS를 구분하고 지연 누적·탐지 품질로 판단한다. 종전 매 프레임30FPS 달성을 후속 WBS의 일괄 선행 조건으로 삼지 않는다. 기존 실패는 보존하며15FPS 관측만으로 품질/운영 합격을 선언하지 않는다.
현재 자료만으로 달성·불가능 또는 장비 교체 필요를 확정하지 않는다. 다음 검증은
**계측/실행 버전 확인 → 전체 AI 1채널 → 2채널 → 4채널** 순서다.
관제 선정 전에도 모델별 완료·누락·영상 적체의 검증 준비는 진행할 수 있다.

09-21 [공유 GPT 대화의 적용 검토](MULTICAMERA_ARCHITECTURE_REVIEW.md)에서 실행 컨테이너의
pyds 1.2.0·DeepStream 플러그인 7.1.0과 설정을 읽기 전용으로 확인했다. pyds 추가 도입보다
현재 계측·엔진·후처리·복구 경계 대조가 우선이다. 설치/설정 확인이며 성능을 재측정한 것은 아니다.

## 재계산한 근거

09-17의 Primary 초기 시험, 해상도 비교, L1/L3 비교, AI 일시정지 비교에서
보고서 26개·카메라 측정 구간 80개를 재계산했다. 워밍업을 제외한 시작 표본은
`마지막 monotonic - elapsed_seconds`와 일치하는 유일한 표본으로 선택했다.
FPS는 tensor 누적 수의 차이를 실제 경과 시간으로 나눴고, 적체 증가는
`pipeline running time - source PTS`의 끝/시작 차이로 계산했다.
원본 해시·선택 표본·카메라별 값·공식은 [재계산 JSON](evidence/primary_recalculation_20260918.json)에 있다.
모든 선택 보고서는 정상 종료했고, 재계산값은 기존 집계와 일치했다.

| 시험 조건 | 카메라 중 최저 tensor FPS | 해당 측정 구간의 최대 적체 증가 |
|---|---:|---:|
| L3 / 1080p / 1채널, 약 60초 | 29.96 | 0.005초 |
| L3 / 1080p / 2채널, 약 30초 | 24.43 | 5.59초 |
| L3 / 1080p / 4채널, 약 30초 × 3회 | 평균 13.99 (13.58~14.28) | 15.76~16.42초 |
| 해상도 비교 / 1080p / 4채널, 약 30초 × 3회 | 평균 13.93 | 15.37~16.48초 |
| 해상도 비교 / 720p / 4채널, 약 30초 × 3회 | 평균 13.16 | 16.37~17.16초 |
| L3 / 4채널 / 운영 AI 정지 전·일시정지·복원 후 | 28.79 / 21.77 / 14.48 | 1.16 / 8.19 / 15.52초 |

이는 **녹화 입력의 decode + Primary만** 측정한 결과다. 낙상·헬멧·의상·색상
전체 완료 FPS, 실물 4대, 장치 출력·관제까지의 지연을 증명하지 않는다.
공유 GPU/데스크톱 부하와 시간대가 달라 비교값을 특정 최적화의 인과 효과로
해석하지 않는다. 720p 입력에서도 모델 입력은 640이며, 위 결과로 해상도 축소의
일반적인 효과를 단정하지 않는다. 53초 AI 일시정지는 GPU 문맥·메모리가 남는
제한된 실험이므로 전용 장비의 성능을 대신하지 않는다.

초기 보고서의 `bInferDone` 기반 inferred FPS는 잘못 집계됐다. 이번 계산은 별도
`tensor_frames`를 사용했다. 이후 교정된 계측도 현재 운영 프로세스에 로드됐는지는
미확인이다(I07). 모델 파일 존재/해시와 실제 실행 모델·코드 반영을 구분한다.

## 2026-09-30 — DLA 적용 판단

**권고: GPU 기준 안정화 후 모델 하나씩 DLA를 비교하는 P6.2 후보로 유지한다.**
실장비는AGX Orin이며 동일 격리 이미지의 TensorRT10.3 `Builder.num_DLA_cores`가2를 반환했다.
모델 실행/속도/전력은 측정하지 않았고 현재 엔진·운영 설정은 변경하지 않았다.
[NVIDIA DS7.1 안내](https://docs.nvidia.com/metropolis/deepstream/7.1/text/DS_Quickstart.html#using-dla-for-inference)는 GPU/DLA 병행 추론을 지원한다.

DLA는 학습된 신경망의 지원 연산을 수행한다. NVDEC/NVENC·VIC·GPU 전처리·Python 후처리 전체를 대체하지 않으므로
현재 CUDA700의 원인 제거 수단으로 판정하지 않는다. 고정 shape/FP16 또는INT8 엔진과 지원 계층 확인이 필요하고,
미지원 계층이GPU로 돌아가는 경우 전환·복사 비용까지 측정한다.
[NVIDIA DLA 제약 참고—지원되는 이전 릴리스용](https://docs.nvidia.com/deeplearning/tensorrt/latest/inference-library/dla-layer-restrictions.html).

첫 후보는 고정된 인물ROI를 입력하는 의상 분류다. 이는 시험 우선순위 판단이며 해당 모델의DLA 지원/성능을 보장하지 않는다.
Primary Pose와 여러 모델을 동시에 이관하지 않는다. GPU 모델과 같은 입력/정답으로 결과·지연P95·처리량·GPU/DLA 점유·메모리·전력을 비교하고,
출력까지의 지연과 누락이 악화되면 채택하지 않는다. INT8은 별도 대표 보정 데이터와 정확도 검증이 필요하다.
기존 GPU 엔진은 보존하고 DLA용 후보를 별도 빌드한다. R09 목표나 P5.1 종료 기준은 변경하지 않는다.
[DLA2코어 조회 근거](evidence/cuda_comparison_20260930.json).
