### 원인이 확인된 구간과 미확정 구간

- 인덱싱7→13개 동시 실행과 CPU 포화가 겹친 구간을 확인했다. 설치0.9.0의 잠금은 프로세스 내부에만 있어 동일 root의 여러 watcher를 직렬화하지 못했다. 자동감시/자동시작을 끄고 직접 `index_repository`를 비활성화했으며, 수동 갱신은 공용 flock·CPU1개·nice19·I/O idle 진입점으로 제한했다. 검색은 유지하지만 자동 갱신이 꺼져 **실제 파일과 그래프를 대조해야 한다**.
- 공식 MCP reload는14:13:56에 전체 loaded threads의 설정 refresh를 예약했다. codebase-memory만의 재연결로 한정한 호출은 아니며, 다른 MCP별 일시 지연은 측정하지 않았다. 명시적 채팅 interrupt·프로세스 kill·운영 재시작은 없었다.
- 이후 worker0에서도 처리율 저하가 재발했다. **14:22~28의 저하 원인은 미확정**이며 전부 인덱싱 탓으로 묶지 않는다.
- 사용자 PoE 연결 전환과 함께 eno1이14:34:25~14:37:44에199초 단절됐다. EOS와 두 RTSP SDP timeout이 이 구간 안에 있어 해당 입력 실패는 링크 단절로 설명된다.14:38부터 입력 자체 복구가 관측됐으나 이를 이후 지속 회복이나 시험 승인으로 사용하지 않는다.

### Windows 미니PC 저장 POC

사용자 확인 사양은 **Windows10·128GB·192.168.0.20·계정 ecs**, 스위치 유선 연결이다. 우선 저장 범위는 탐지 결과·센서값·이벤트 이미지이며 상시 영상 녹화는 제외한다. 합성 기록2종+JPEG1장 총3,348bytes를 로컬에서 준비했지만 **원격 인증·쓰기·읽기 대조는 미실행**이다.

사용자가 `C:\ProgramData\ssh\ssh_host_ed25519_key.pub`에서 확인했다고 제공한 지문과 이전 SSH 응답 지문은 전체 문자열이 다르다. Windows 연결 이더넷 IPv4/MAC와 실제 sshd 키를 대조하기 전 신뢰·인증·전송을 보류한다. IP중복·다른 장비 응답·키 변경·sshd 설정 중 원인은 미확정이다. B의 비활성 `.0.20/24` 프로필도 있어 활성화 전 주소 재조율이 필요하지만 현재 IP충돌을 확정한 것은 아니다.

근거: [장비·전체 지문·저장 범위](POC_SCOPE.md#minipc-storage-20261023), [개발도구·배정 기록](../tooling/CODEX_SKILL_ADOPTION.md).

## 7. Git 반영 범위와 작업 보존

이번 마감 커밋은 **주간보고·공통 계획/상태·관련 검증 근거·병렬 작업 규칙**을 대상으로 한다. 기존 index에 누적된 무관한 제품/배포/시험 변경을 일괄 커밋하지 않는다. 보고된 구현·운영 반영과 이 문서 커밋의 범위는 다르다.

`codex/edge-auto-failback`, `codex/multicamera-engine-batch`, `codex/two-camera-baseline`, `codex/camera-offload`의 전용 worktree와 미통합 변경은 보존한다. 이들의 개발 기준은 `fefa4ab04ee2ca26bbc0ee433381e4b7648265e7`이며 이번 문서 커밋만으로 소스 통합·제품 합격이 되지 않는다. 원시 영상·엔진·DB·인증정보·개별 worktree의 전체 산출물은 문서 패키지에 포함하지 않는다. 저장 근거의 경로·해시와 최종 판정은 공통 JSON에 남긴다.

검증 범위: 보고서의 상대 링크, 참조 JSON 구문, WBS37개/DONE9개 정합, 시험/반환 상태 대조, 커밋 경로·민감정보 패턴·diff 검사를 수행한다. 마감 과정에서 제품 회귀·GPU·새 SSH·운영 회복 관측을 수행하지 않으며, 과거 시험 PASS를 새 소스 전체 합격으로 표현하지 않는다.

Git의 기존 pre-commit 훅은 그래프 갱신, pre-push 훅은 전체 `ruff --fix`와 `pytest tests/`를 실행한다. 운영 부하 보류와 기존 미커밋 파일 보존을 위해 이번 문서 커밋에는 명령 단위 `core.hooksPath=/dev/null`, 푸시에는 훅이 제공하는 `SKIP_PRE_PUSH_CHECKS=1`을 사용한다. 공유 훅/설정은 변경하지 않으며 위 문서 검증을 수행한다. 이는 제품 전체 회귀 통과를 뜻하지 않는다.
