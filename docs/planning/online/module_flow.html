이벤트 한 건은 이렇게 이동합니다

  1. 영상·센서 입력: DeepStream이 AI 이벤트를 만들고, TLV 파서는 센서값을 해석합니다.
  2. MQTT 전달·규칙: Action의 직접 구독과 eKuiper를 거치는 경로가 함께 있습니다. 모든 AI 이벤트가 규칙을 통과하는 구조는 아닙니다.
  3. Action 판단: 입력 정규화·사이트/정책 적용 후 장치별 명령을 생성하고 실행 이력을 기록합니다.
  4. 장치 명령·결과: Device Service가 장치 프로토콜로 출력하고, 결과 MQTT를 Action이 받아 상태를 갱신합니다.

저장 ACK → 입력 처리 완료 → 장치 결과 → 실물 확인은 각각 다른 확인 단계입니다.

이번 후보에서 바뀐 구간

MQTT 수신 → SQLite 원본 저장 → ACK를 먼저 끝내고, 별도 작업자가 기존 Action 처리를 호출합니다.

  • 느린 장치 처리 중에도 후속 입력을 저장합니다.
  • 재시작 잔여 입력·실행 결과가 불명확한 입력은 보류합니다.
  • 수신 전용 모드는 장치 명령과 HTTP 전달을 실행하지 않습니다.
  • 자동 재개는 P3.1 우선순위·만료·장치별 순서 검증 후 결정합니다.
