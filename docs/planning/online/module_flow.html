AI 직접 구독과 센서 규칙 경로를 구분한 요약입니다. 저장 상세는 아래 표에서 확인하세요.

입력에서 실제 출력까지

  1. 영상: CCTV의 RTSP → Jetson DeepStream → 사람 탐지·추적·낙상 등 → 이벤트 발행. 분석 모델의 실행 여부와 품질 합격은 별도입니다.
  2. 센서: 게이트웨이 MQTT → TLV 파서 → 센서 MQTT 발행과 EdgeX Core Data HTTP 전송으로 분기합니다. 센서 규칙은 MQTT를 구독하며 Core Data 뒤의 필수 단계가 아닙니다.
  3. 판단: Action Bridge는 AI 직접 구독과 규칙 이벤트를 처리합니다. 정책·만료·물리 장치별 대기·미확정 보류 구현은 운영 적용 여부와 구분합니다.
  4. 출력: EdgeX·Device Service → 장치 명령 → 결과 수집. 전광판 실물 확인과 스피커·사이렌 검증을 하나의 합격으로 묶지 않습니다.

A/B 작업 이전의 범위

  • Agent의 자원·실행 보고 → 오케스트레이터 판단 → 카메라별 담당·실행 세대 관리 → 시작/중지 인계입니다.
  • AI 결과는 Relay → DDS 또는 MQTT → 중앙 원본 저장으로 전달합니다. 저장 ACK 확인과 재전송은 영상 전송과 별도입니다.
  • 현재 담당 미리보기는 2초 간격·최대640px JPEG POC입니다. 연속 RTSP/HLS 재생 합격을 뜻하지 않습니다.
  • B가 A의 SSH 터널을 통해 입력받은 실증은 A 전체 장애 시 독립 입력을 보장하지 않습니다.
