# ADR-001: EdgeX를 현장 장치 제어의 표준 경계로 사용

## 상태

Accepted

## 날짜

2026-09-04

## 배경

이 프로젝트의 목적은 Jetson 기반 Edge AIoT 시스템으로 현장 상황을 실시간 분석하고, 위험 상황을 감지하면 스피커·사이렌·전광판 등의 장치를 빠르게 제어하는 것이다.

현재 Action Layer에는 장치별 직접 호출과 EdgeX Command Shadow 발행 경로가 함께 존재한다. 이 상태에서는 장치 프로토콜과 경보 정책이 한 계층에 섞이고, 장치가 늘어날수록 장애 격리와 운영 전환이 어려워진다.

## 결정

AI 이벤트가 생성된 이후의 현장 장치 제어 표준 경계로 EdgeX Core Command와 Device Service를 사용한다.

- AI 추론과 이벤트 정규화는 Jetson 로컬 애플리케이션이 담당한다.
- Action Layer는 위험도, 중복 억제, 승인, `device_id` 대상 선정을 담당한다.
- EdgeX Core Command는 공통 명령을 장치 서비스로 전달한다.
- Device Service는 스피커·사이렌·전광판별 물리 프로토콜을 담당한다.
- 명령 결과는 `event_id`와 `request_id`를 기준으로 저장한다.
- 실제 장치 UAT 완료 전까지 direct 모드와 shadow 모드를 롤백 수단으로 유지한다.

## 대안

### 장치별 직접 호출 유지

- 장점: 현재 코드 변경이 적고 초기 연결이 빠르다.
- 단점: 장치 프로토콜이 Action Layer에 계속 누적되고, 다중 장치 장애 격리가 어렵다.
- 결정: 단기 fallback으로 유지하지만 목표 운영 구조로는 선택하지 않는다.

### AI 애플리케이션에서 장치를 직접 제어

- 장점: 호출 경로가 짧아 보인다.
- 단점: 실시간 추론과 장치 장애·재시도·프로토콜 처리가 결합된다.
- 결정: Edge AIoT의 유지보수성과 확장성을 해치므로 선택하지 않는다.

## 결과

### 긍정적 결과

- 장치 종류가 늘어도 Action Layer의 경보 정책을 반복 구현하지 않는다.
- `device_id` 기반 다중 장치 제어와 장애 격리가 쉬워진다.
- 장치 명령 결과와 지연시간을 공통 형식으로 기록할 수 있다.
- 실제 장치가 없는 환경에서 Device Service 계약을 시뮬레이션으로 검증할 수 있다.

### 부담과 위험

- EdgeX 서비스와 Device Service 운영 구성이 추가된다.
- direct에서 EdgeX로 전환하는 동안 중복 발행과 결과 불일치가 발생할 수 있다.
- 네트워크·메시지 브로커 장애 시 fallback과 재시도 정책을 별도로 검증해야 한다.

## 후속 작업

- [ ] shadow 모드에서 direct와 EdgeX 결과 비교
- [ ] 장치별 실제 UAT 및 timeout/retry 검증
- [ ] 사이트 단위로 EdgeX 제어 활성화
- [ ] 운영 기준 충족 후 direct 경로 제거 여부 결정
