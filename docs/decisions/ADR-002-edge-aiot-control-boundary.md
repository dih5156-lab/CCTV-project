# ADR-002: 실시간 Edge AIoT 제어 경계 보완

## 상태

Accepted

## 일자

2026-09-04

## 문맥

전임자 SEdge-Platform은 Event Receiver, Platform Bridge, Device Manager, 디바이스별 제어 모듈을 분리했다. 이 방향은 확장성 측면에서 유효하지만, 제조사 API·Socket·GPIO 호출이 플랫폼 코드와 가까이 있고 단일 디바이스 가정이 존재했다.

현재 프로젝트는 EdgeX Device Service와 다중 장치 라우팅을 추가했지만, Action Layer에 정책·장치 선택·전송·결과 저장 책임이 일부 함께 남아 있다. 프로젝트 목적은 외부 서버 응답을 기다리는 것이 아니라 Jetson에서 현장을 빠르게 판단하고 로컬 장치를 제어하는 것이다.

## 결정

다음 경계를 기준으로 구조를 보완한다.

```text
입력·AI·센서
  → 공통 이벤트
  → MQTT/eKuiper
  → Action Policy
  → 공통 Command
  → EdgeX Core Command
  → 장치별 Device Service
  → 실제 장치
```

- 실시간 제어는 로컬 데이터 평면에서 수행한다.
- AI Engine은 장치 제조사 프로토콜을 직접 호출하지 않는다.
- Action Layer는 정책·승인·cooldown·장치 매핑·공통 명령 생성에 집중한다.
- 제조사 HTTP·TCP·GPIO 변환은 Device Service에만 둔다.
- 이벤트와 명령은 분리하고 상관관계 ID를 유지한다.
- 실제 장치 UAT 전까지 Direct/Shadow/EdgeX 전환 플래그와 안전한 롤백을 유지한다.

## 대안

### 기존 직접 호출 유지

- 장점: 현재 장치가 연결된 환경에서 빠르게 동작
- 단점: 장치별 프로토콜 결합, 다중 장치·장애 격리·감사 어려움
- 결정: 롤백·비교용으로만 한시 유지

### 모든 판단을 eKuiper로 이동

- 장점: 규칙 중앙화
- 단점: 복잡한 Pose·시간 상태·물리 계산 표현이 어려움
- 결정: eKuiper는 threshold·window·라우팅 중심으로 사용

### 모든 제어를 외부 IoT 플랫폼을 통해 수행

- 장점: 중앙 관리와 통합 관제
- 단점: 네트워크 장애 시 현장 즉시 제어 불가
- 결정: 외부 플랫폼은 보고·관리 평면으로 두고 현장 제어는 로컬 우선

## 결과

### 긍정적 영향

- 장치 교체 시 Device Service만 변경 가능
- 장치별 timeout·retry·장애 격리 가능
- 정부과제 요구사항과 시험 증빙을 기능 단위로 연결 가능
- EdgeX 전환과 Direct 롤백을 독립적으로 검증 가능

### 비용과 주의점

- 명령·결과 계약을 먼저 고정해야 한다.
- EdgeX 서비스와 MQTT 토픽 운영 부담이 증가한다.
- 실제 장치 UAT가 없으면 물리 제어 성공을 주장할 수 없다.
- Action Layer 책임 분리는 단계적으로 진행해야 기존 운영 경로를 보호할 수 있다.

## 검증 기준

- [ ] 동일 이벤트가 장치별로 한 번만 실행됨
- [ ] 등록되지 않은 장치가 차단됨
- [ ] 한 장치 장애가 다른 장치 실행을 막지 않음
- [ ] EdgeX 명령 결과와 물리 장치 결과가 구분됨
- [ ] 외부 서버가 중단되어도 로컬 제어가 지속됨
- [ ] Direct 모드로 즉시 롤백 가능함
