# ADR-003: EdgeX 출력 장치의 timeout·재시도 정책

## Status

Accepted

## Date

2026-09-07

## Context

EdgeX Device Service는 현장 장치의 네트워크 오류를 Action Layer와 분리해
처리해야 한다. 그러나 모든 장치에 동일한 자동 재시도를 적용하면 스피커
음성 중복 재생이나 사이렌 중복 동작이 발생할 수 있다.

현재 장치별 통신 방식과 동작 특성이 서로 다르다.

| 장치 | 통신 | 현재 timeout | 현재 재시도 | 중복 실행 위험 |
|---|---|---:|---:|---|
| 전광판 | TCP stateless | 소켓 3초 | 연결·전송 최대 3회 | 낮음. 동일 표시 재전송 허용 |
| 스피커 | HTTP Digest | 연결 3초, 응답 7초 | 없음 | 높음. 음성 중복 재생 가능 |
| 사이렌 | HTTP Digest | 연결 3초, 응답 7초 | 없음 | 중간. 자동 정지 타이머와 충돌 가능 |

## Decision

1. timeout은 장치 클라이언트가 소유한다. Device Service는 timeout을 넘긴
   호출을 `failed`와 장치별 오류 코드로 변환해 결과 MQTT에 발행한다.
2. 전광판은 현재 구현된 stateless TCP 최대 3회 재시도를 유지한다.
3. 스피커와 사이렌에는 자동 재시도를 추가하지 않는다. 운영자가 동일
   `event_id`를 확인한 후 명시적으로 재요청한다.
4. Device Service 결과의 `request_id`는 재시도 여부와 무관하게 최초
   Command의 논리 요청 ID를 유지한다. 전광판 내부 재시도는 같은 요청의
   전송 재시도이며 별도 Command로 기록하지 않는다.
5. EdgeX Command MQTT 발행 성공은 장치 동작 성공이 아니다. Action Layer의
   초기 상태와 Device Service의 최종 결과를 구분한다.
   - 초기 발행: `acknowledged`(MQTT 발행 및 처리 접수)
   - 장치 결과: `acknowledged` 또는 `failed`
6. 자동 재시도가 필요한 새 장치는 다음 조건을 만족할 때만 장치별로
   추가한다.
   - 명령이 멱등적이다.
   - 재시도 횟수와 backoff가 설정으로 고정된다.
   - `request_id` 중복 결과가 저장소에서 갱신 처리된다.
   - 실제 장치에서 중복 동작이 발생하지 않음을 UAT로 확인한다.
7. 세 Device Service는 처리 완료한 `request_id`와 결과를 프로세스 내
   제한 캐시에 보관한다. 같은 요청이 MQTT QoS 재전달로 다시 들어오면
   기존 결과를 반환하고 물리 장치 메서드를 다시 호출하지 않는다.
   `failed` 결과는 캐시하지 않아 장애 복구 후 재요청할 수 있게 한다.

## Alternatives Considered

### 모든 장치에 공통 3회 재시도

구현은 단순하지만 스피커 음성 중복 재생과 사이렌 반복 동작을 만들 수
있어 Edge AIoT 실시간 제어 목적에 부적합하다.

### Action Layer에서 재시도

장치 프로토콜과 무관하게 처리할 수 있지만, 물리 장치별 timeout과 멱등성
정보가 Action Layer에 섞여 장치 장애 격리가 약해진다.

### Device Service별 정책 분리

장치별 특성을 반영하고 장애 범위를 분리할 수 있어 채택한다. 설정과
결과 계약이 장치별로 흩어질 수 있으므로 이 ADR과 UAT 기록으로 기준을
고정한다.

## Consequences

- 현재 전광판은 일시적인 TCP 연결 오류를 내부 재시도로 흡수한다.
- 스피커·사이렌은 빠르게 실패를 반환해 이벤트 처리 스레드를 오래
  점유하지 않는다.
- 실패 시 자동 복구보다 중복 물리 동작 방지를 우선한다.
- 스피커·사이렌 실제 장치가 연결되면 timeout과 재시도 필요성을 장치별
  UAT로 재평가해야 한다.
- `request_id`, `event_id`, `device_id`, `status`가 있어야 성공·실패를
  추적할 수 있다.
- Device Service 재시작 시 멱등성 캐시는 초기화된다. 브로커 또는 상위
  계층에서 재시작 경계를 넘는 중복까지 차단해야 하는 경우에는 결과 DB
  기반의 영속 멱등성 저장소를 별도 설계해야 한다.
