# 보호형 통합 외형 속성 모델 설계

## 1. 목적

사람 검출·추적 결과를 이용해 실시간 화면에 추가 박스를 표시하지 않으면서 다음 속성을 판별하고 검색 가능한 기록으로 남긴다.

- 성별
- 상의·하의 색상
- 상의·하의 의류 종류
- 가방, 백팩, 모자, 마스크 유무
- 추적 ID당 대표 이미지 1장

색상 성능이 약한 기존 속성 모델을 그대로 확대하지 않는다. 새 11색 학습 결과를 색상 기준선으로 보존하고, 통합 모델의 색상 성능이 기준을 통과할 때만 운영 모델을 교체한다.

## 2. 범위

### 2.1 1차 모델에 포함

- 성별: 여성, 남성
- 상의 색상: black, white, gray, red, blue, green, yellow, brown, purple, navy, orange
- 하의 색상: 상의와 동일한 11색
- 상의 종류: long_sleeve, short_sleeve, sleeveless
- 하의 종류: long_pants, short_pants, long_skirt, short_skirt, dress
- 소지품: bag, backpack, hat, mask

### 2.2 이번 단계에서 제외

- 휴대전화, 안경, 선글라스, 우산, 물병 등 작은 물건
- 소지품 위치를 표시하는 별도 객체 검출 모델
- 사람 재식별 임베딩 모델의 변경
- 낙상 모델과 낙상 파이프라인의 변경
- 기존 이미지 보관·삭제 기간 정책의 변경

## 3. 현재 모델의 역할

### 3.1 운영 모델

운영 경로의 PA100K TensorRT 속성 모델, HSV/LAB 색상 처리, 기존 색상 엔진은 새 후보가 승격될 때까지 유지한다. 새 학습이 실패하거나 성능 기준을 통과하지 못해도 운영 결과는 바뀌지 않는다.

### 3.2 11색 시험 모델

`aihub_kreid.resnet50.native11.smoke1` 체크포인트는 운영 모델이 아니라 다음 용도로 사용한다.

- 11색 라벨·학습 파이프라인 기준선
- 통합 모델의 백본 및 색상 가중치 초기화 후보
- 같은 holdout에서 통합 모델과 비교할 전용 색상 기준선

1 epoch 시험 결과이므로 최종 운영 후보로 직접 승격하지 않는다.

### 3.3 9색 시험 결과

9색 시험은 정상 체크포인트가 없으므로 로그와 지표만 비교 자료로 보존하고 학습 초기값이나 운영 후보로 사용하지 않는다.

## 4. 선택한 모델 구조

하나의 사람 이미지 백본을 공유하되 출력과 손실은 작업별로 분리한다.

- 성별 헤드: 단일 선택 분류
- 상의 색상 헤드: 11색 단일 선택 분류
- 하의 색상 헤드: 11색 단일 선택 분류
- 상의 종류 헤드: 3종 단일 선택 분류
- 하의 종류 헤드: 5종 단일 선택 분류
- 소지품 헤드: bag, backpack, hat, mask 다중 라벨 분류

색상·의류처럼 동시에 하나만 선택되는 그룹은 그룹별 분류 손실을 사용한다. 여러 개가 동시에 존재할 수 있는 소지품은 독립 sigmoid 손실을 사용한다. 모든 출력을 하나의 평면 BCE로 처리하지 않는다.

## 5. 색상 성능 보호 전략

통합 학습으로 인한 negative transfer를 막기 위해 두 단계로 학습한다.

1. 보호 학습
   - 11색 체크포인트에서 호환되는 백본 가중치를 불러온다.
   - 11색 출력층의 상·하의 색상 행은 새 색상 헤드의 대응 클래스에 복사한다.
   - 백본과 색상 헤드는 완전히 고정한다.
   - 새 성별·의류·소지품 헤드를 우선 학습한다.
2. 공동 미세조정
   - 백본과 색상 헤드를 해제하고 새 헤드 학습률의 0.1배를 적용한다.
   - 작업별 손실 가중치를 독립적으로 기록한다.
   - 색상 성능이 하락하면 해당 epoch를 후보에서 제외한다.

색상 기준을 통과하지 못하면 통합 배포를 강제하지 않고 색상 전용 모델과 나머지 속성 모델을 분리한 2모델 구성을 사용한다.

## 6. 데이터 구성

### 6.1 입력 데이터

- AI-Hub K-ReID 전체 고해상도 PNG/XML
- `defined_*_color=true`인 색상 라벨
- 유효한 성별·의류 종류 라벨
- ITEM_LIST의 bag, backpack, hat, mask 라벨

`defined=false`인 색상은 음성 라벨로 바꾸지 않고 해당 색상 손실에서 제외한다. 파싱 실패, 잘린 신체, 해당 부위 미노출도 가능한 경우 작업별 마스크로 손실 계산에서 제외한다.

### 6.2 샘플링

- 초기 목표: 5만~10만장
- 동일 사람·세션·카메라의 연속 프레임 중복 억제
- 희귀 색상과 소지품 우선 보존
- 색상·의류·소지품별 학습 표본 수 보고서 생성
- train/validation/test는 사람 ID 기준으로 완전히 분리

하의 orange처럼 검증 표본이 부족한 속성은 운영 지원 완료로 판정하지 않는다. 최소 30개의 독립 검수 표본을 확보하기 전까지 해당 속성은 실험 상태로 보고하고, 추가 검수 또는 공개 데이터로 보강한다.

## 7. 실시간 처리 흐름

1. 기존 사람 검출·추적 결과를 사용한다.
2. 매 프레임이 아니라 추적 ID별 기본 0.5초 간격으로 속성 추론을 실행한다. 간격은 운영 설정으로 변경할 수 있다.
3. 너비 48px 또는 높이 96px 미만의 crop은 속성 추론에서 제외하고 unknown으로 유지한다.
4. 추적 ID별로 여러 프레임의 속성과 신뢰도를 누적한다.
5. 다수결과 신뢰도 가중 투표로 최종 속성을 결정한다.
6. 가장 품질이 좋은 대표 이미지 1장을 유지한다.
7. 추적 종료 시 최종 속성, 신뢰도, 시각, 카메라, 내부 bbox, 대표 이미지 경로를 저장한다.

내부 bbox는 crop 생성과 증거 확인에만 사용한다. 실시간 영상에는 bbox와 속성 텍스트를 추가로 그리지 않는다.

## 8. 대표 이미지 정책

추적 ID마다 디스크에 최종 1장만 남긴다. 후보 품질은 다음 순서로 평가한다.

- 상·하의 가시성
- 사람 crop 크기
- 흐림 정도
- 잘림 정도
- 통합 속성 신뢰도

추적 중 더 좋은 후보가 나오면 이전 임시 후보를 교체한다. 추적 종료 후 최종 대표 이미지만 검색 증거로 유지한다. 이미지 보관 기간은 기존 운영 보관 정책을 그대로 사용한다.

## 9. 검색 및 통계 데이터

검색 레코드는 최소한 다음 정보를 제공한다.

- camera_id, track_id
- first_seen, last_seen
- gender 및 confidence
- upper_color, lower_color 및 confidence
- upper_clothes, lower_clothes 및 confidence
- bag, backpack, hat, mask 및 confidence
- representative_crop_path
- model_version, label_map_version

검색 화면에서는 색상·의류·소지품 조건 조합, 시간 범위, 카메라 조건으로 필터링하고 대표 이미지와 집계 건수를 보여준다. 실시간 화면 표시는 이번 범위에 포함하지 않는다.

## 10. 평가와 승격 기준

### 10.1 정확도

- 성별·의류·소지품: 클래스별 precision, recall, F1과 macro F1 보고
- 색상: 상의·하의를 분리하고 11색별 precision, recall, F1, mA 보고
- 통합 평균만으로 승격하지 않음
- 같은 데이터·epoch 조건의 11색 전용 후보 대비 공통 색상의 macro F1 하락이 0.02를 넘으면 통합 색상 경로 승격 금지
- 개별 공통 색상의 F1 하락이 0.05를 넘으면 원인을 검토하고 해당 후보 승격 금지
- 검증 표본이 30개 미만인 클래스는 통과가 아니라 평가 보류로 처리

### 10.2 Jetson 성능

- TensorRT 후보를 실제 운영 해상도와 카메라 수로 측정
- 속성 추론 p95 지연시간이 현재 두 속성 경로의 합보다 느리지 않아야 함
- 30분 shadow 테스트에서 프레임 드롭률이 기존 대비 1%p 이상 증가하면 승격 금지
- 메모리 증가량과 GPU 사용률을 보고서에 기록

### 10.3 기능 안정성

- 모델 또는 라벨맵 로드 실패 시 기존 운영 모델 유지
- 낮은 신뢰도는 임의 색상·속성 대신 unknown으로 저장
- 새 DB 필드를 읽지 못하는 기존 소비자는 기존 필드로 계속 동작

## 11. 배포 단계

1. 데이터셋과 라벨 통계 생성
2. 11색 전용 기준선 재학습 및 고정 holdout 평가
3. 보호형 통합 모델 학습
4. 전용 색상 모델과 통합 후보 비교
5. ONNX 내보내기 및 출력 일치 검증
6. TensorRT 변환 및 Jetson 성능 측정
7. 운영 결과에 영향 없는 shadow 추론
8. 정확도·성능 기준 통과 시 제한된 카메라에서 candidate 활성화
9. 문제 없을 때 기본 모델로 승격

기존 PA100K, 색상 엔진, 11색 체크포인트는 롤백 가능하도록 삭제하지 않는다.

## 12. 테스트 계획

- XML 라벨 파싱 및 unknown mask 단위 테스트
- 사람 ID 분할 누수 테스트
- 희귀 클래스 보존 샘플링 테스트
- 작업별 출력 차원과 라벨맵 일치 테스트
- 체크포인트 부분 로딩과 색상 가중치 보호 테스트
- 작업별 loss mask 및 class weight 테스트
- PyTorch/ONNX/TensorRT 출력 허용 오차 테스트
- 추적 투표와 대표 이미지 1장 교체 테스트
- 검색 레코드 직렬화·역직렬화 테스트
- 운영 모델 fallback 테스트
- Jetson shadow 처리량 및 프레임 드롭 테스트

## 13. 완료 조건

- 고정된 사람 ID 분리 데이터셋과 라벨 통계가 재현 가능하다.
- 1차 범위의 모든 출력에 클래스별 평가 결과가 존재한다.
- 색상 보호 기준을 통과하거나, 실패 시 2모델 fallback 구성이 선택된다.
- 대표 이미지는 추적 ID당 1장만 남는다.
- 실시간 화면에 추가 bbox를 표시하지 않는다.
- 운영 승격 전까지 기존 모델과 데이터 경로가 바뀌지 않는다.
