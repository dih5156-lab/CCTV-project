# Jetson Pose L1/L3 엔진 비교 — 2026-09-17

## 범위와 상태

TensorRT optimization level 3 후보 빌드와 8개 재생 시험이 종료됐다.
4채널 평균은 기존 L1 **13.39FPS**, 새 L3 **13.99FPS**로, 현재 공유 부하 조건에서
**4채널×30FPS 미달**이다. **운영 적용/정확도/상용 승인 아님.**
이 후보는 Pose TensorRT 엔진이며, 기존 낙상 시계열 Candidate 모델과는 별개다.

후속 비교 대상은 [해상도 비교](JETSON_POSE_RESOLUTION_COMPARISON_20260917.md)에서
사용한 L1 엔진이다. 운영 파일, 카메라 설정, 전력 모드는 변경하지 않았다.

## 빌드와 재현 조건

- 결과 위치: `data/benchmarks/pose_l3_build_20260917.1QDRpB/`.
- 장비: Jetson AGX Orin, TensorRT 10.3.0, DeepStream 7.1, MODE_30W(2).
- 빌드 시작/종료: 2026-09-17 16:00:21~16:15:15 KST.
  trtexec 엔진 빌드 시간 887.402초, 프로세스 종료 코드 0, deserialize 0.0879602초.
- 기존 output-only ONNX를 그대로 사용: min=1, opt=max=4, 입력 3×640×640,
  FP16 허용, builderOptimizationLevel=3, avgTiming=1, workspace=1024MiB.
  FP16 허용은 모든 레이어가 FP16이라는 뜻이 아니다.
- L1 timing cache를 private 디렉터리로 복사하여 탐색을 시작했다. 원본 cache는 수정하지 않았다.
- 컨테이너: `--network none`, read-only rootfs, 입력 read-only,
  결과 디렉터리만 쓰기 가능. 앱 runner, MQTT/EdgeX 연결, 장치 제어 소켓 없음.
- 빌드 제한 1800초/12GiB/CPU 4개. 수동 tegrastats 표본에서 최대 54.562°C를 관측했다.
  연속 최고 온도나 자동 열 차단의 증거는 아니다. 재생 시험의 안전 감시와 구분한다.
- 운영 카메라 1개와 데스크톱 앱이 실행 중인 공유 부하 시험이다.
  추가 재생 4개는 총 5개 입력 경로가 공존하는 조건이며, 실물 4대 단독 시험이 아니다.

## 출력 진단 — 정확도 평가 아님

동일 원본 영상의 요청 시각 5/15/25/35초 프레임 4개를 기존 비교 도구로 확인했다.
전처리는 640 RGB float32 /255, 종횡비 유지 resize, 대칭 114 padding이다.
두 비교의 입력 tensor 해시가 일치하며, L3 출력은 `(batch,56,8400)` 유한값이다.

| 비교 | 전체 최대 절대 차이 | 평균 절대 차이 | 사람 점수 최대 차이 | foreground 최대 차이 | atol/rtol=0.001 allclose |
| --- | ---: | ---: | ---: | ---: | --- |
| 운영 엔진 → L3, batch 1 | 6.5 | 0.045964 | 0.004123 | 2.0 | false |
| L1 → L3, batch 1 | 5.75 | 0.041922 | 0.002897 | 1.5 | false |

foreground는 양쪽 사람 점수 0.25 이상인 proposal 합집합 23개이다.
좌표/점수 등 서로 다른 의미의 tensor 성분을 포함하므로 전체 차이를 정확도나
최종 관절 오차 하나로 해석하지 않는다. L3의 batch 1 대 batch 2/4는 이 표본에서
최대 차이 0이었다. NMS, 사람 매칭, 낙상 판정, 30초 이후 전체 시계열은 평가하지 않았다.
비교 도구의 default CUDA stream 경고가 있으므로 이 실행 시간을 성능 지표로 쓰지 않는다.

## 재생 시험 계획

`experiment_plan.json`을 결과 측정 전에 기록했다. 원본 1080p 영상, 같은 L1/L3 엔진,
독립 decoder 1/2/4개, shared mux/nvinfer, interval=0을 사용한다. mux 1920×1080,
모델 입력 640×640이며 카메라당 Primary tensor가 실제 붙은 프레임을 센다.

1. L3 1채널: warmup 10초 + 측정 60초.
2. L3 2채널: warmup 10초 + 측정 30초.
3. 4채널 반복: L1→L3 / L3→L1 / L1→L3, 각 warmup 10초 + 측정 30초.

계측 범위는 decode + Primary뿐이다. tracker/NMS/시간 모델/보조 모델/UI/EdgeX는
포함하지 않는다. interval=0 및 tensor count 일치가 원본 입력의 무손실 전체 처리를
입증하지는 않는다. 설정 batch=4도 실제 모든 배치가 4로 채워졌다는 증거는 아니다.
지연은 같은 실행 안의 source PTS 대 pipeline clock 차이의 변화이며 E2E 지연이 아니다.

이번 실행들의 FPS는 같은 실행 내 카메라 사이에 일치했다.

| L1 | 3 | 13.3932 | 0.3280 | 12.5783~14.2080 |

관측 평균 차이는 +4.4721%다. 각 실행의 동기화된 4개 영상을 12개 독립 표본으로
세지 않았다. 통제되지 않은 운영/데스크톱 부하, 실행 수 3개, 정규성/독립성 미검증을
고려해 위 구간을 SLA 보증이나 원인 효과의 증거로 사용하지 않는다. 구간 겹침도
정식 가설 검정을 대신하지 않는다. L3가 요구 성능을 해결했다거나, 현재 수치가
Jetson 단독 성능의 상한이라는 결론을 내릴 수 없다.

1채널 결과는 원본 명목 30000/1001 FPS에 근접하고 지연 증가도 작았다.
2·4채널에서는 지속적인 재생 적체가 발생했다. 이 때문에 단순 화면 FPS나
처리 완료 프레임에 대한 tensor 존재 여부만으로 매 프레임 실시간 처리 합격을 선언하지 않는다.

## 검증과 운영 보존

- 8개 실행 모두 프로세스 종료 코드 0, `finished=true`, `errors=[]`.
  측정 구간의 모든 카메라에서 seen=inferred=tensor, skipped=unknown=0.
- 재생 시험 표본의 최고 온도 55.343°C, 최소 MemAvailable 31.510GiB.
  온도 80°C / 가용 메모리 8GiB 안전 한계 초과 없음. 최초 프레임 부재·프레임 정체
  중단도 발생하지 않았다. 빌드 동안의 연속 계측으로 확대 해석하지 않는다.
- GPU 재생 시험이 모두 끝난 뒤 관련 회귀 테스트 **53 passed (10.63s)**,
  관련 도구/테스트 6개 파일의 Ruff check 통과.
- JSON 원자료에서 FPS=추론 프레임 수/실측 시간을 검산하고, 별도 jq 계산으로
  반복 평균·표본 표준편차·구간을 재계산해 요약과 일치함을 확인했다.
- 운영 AI/API/action-layer는 모두 running/healthy, restart count 0,
  StartedAt도 이전 값과 동일. 이번 시험 컨테이너가 남아 있지 않음을 확인했다.
- MODE_30W(2) 유지. 운영 ONNX/engine/Primary 설정/cameras.json, 원본 영상,
  L1 엔진/cache 및 기존 시험 도구 3개 파일의 SHA-256 유지.
- 일부 선택 플러그인(Rivermax/Triton 등)과 Argus 소켓 미노출 경고는 로그에 보존했다.
  파일 재생 + nvinfer 경로는 완료됐지만, 이 경고를 다른 운영 경로의 정상 증거로 쓰지 않는다.

원자료: `dynamic_l3_build.log`, `dynamic_l3_layers.json`, `experiment_plan.json`,
`paired_production_vs_l3.json`, `paired_l1_vs_l3.json`, 각 실행의 `report.json`/
`primary.txt`/로그, `l3_comparison_summary.json`.
이미지는 `sha256:1ace5b7832a50d6675b66146b0edc307021795732fc7c9a770e2cd628d7fd261`로 고정했다.

이번 변경은 이 보고서, 이전 보고서의 후속 링크, private 후보 엔진·계획·로그·결과뿐이다.
시험/앱 코드, 배포 설정 및 운영 장치는 변경하지 않았다. L3 엔진은 승격하지 않는다.

다음에는 공유 부하와 추론 경로의 병목을 분리하고, 전체 AI 경로 및 NMS/낙상 시계열
정확도를 검증해야 한다. 운영 서비스 중단이나 전력 모드 변경을 포함하는 단독 성능 시험은
현재 승인 범위에 포함하지 않는다. 실물 4대·장시간·장치 UAT도 별도로 남아 있다.

후속 [실행 비용·운영 부하 분리 진단](JETSON_POSE_DISPATCH_AND_COLOAD_20260917.md)에서는
